## Backend

- [x] **Alta** ★ · `backend/src/main/java/br/com/fatec/wave/security/SecurityConfig.java:38` — Não há `@RestControllerAdvice` e a rota `/error` não está liberada. Por isso 400, 404, 409 e 500 viram 403 com corpo vazio (testado: `GET /usuarios/9999`, enum inválido, rota inexistente, e-mail duplicado). **Correção:** criar um `@RestControllerAdvice` com um JSON de erro padrão e liberar `/error` no `SecurityFilterChain`.
- [x] **Alta** ★ · `security/SecurityFilter.java:30-31` e `security/TokenService.java:43` — Token inválido ou expirado lança `RuntimeException` genérica, e o mesmo ocorre se o usuário do token não existe mais. O resultado é 403, inclusive em rotas públicas: `POST /login` com credenciais corretas e token velho no header falha. **Correção:** capturar a falha no filtro e responder 401 em JSON, sem autenticar rotas públicas quando o token for inválido.
- [x] **Alta** ★ · `controller/UsuarioController.java:68-74` e `service/UsuarioServiceImpl.java:88` — Qualquer USER edita qualquer usuário. Testado: um USER trocou a senha do admin (id 1) e o login com a senha nova funcionou, o que permite tomar a conta. **Correção:** no service, permitir a edição só se o id for o do usuário autenticado ou se ele for ADMIN; caso contrário, responder 403.
- [x] **Alta** ★ · `controller/PlaylistController.java:20` — Não existe rota para os dados do usuário logado (`GET /meu-perfil` não existe). **Correção:** criar `GET /meu-perfil`, que resolve o usuário pelo `@AuthenticationPrincipal` e devolve um DTO com id, nome, e-mail e role. **Status:** backend feito (`controller/MeuPerfilController.java`). `frontend/src/components/Header.jsx` e `frontend/src/pages/Perfil.jsx` já usam a rota.
- [ ] **Alta** ★ · `dto/CriarUsuarioDTO.java`, `AtualizarUsuarioDTO.java`, `DadosAutenticacao.java`, `CriarArtistaDTO.java`, `AtualizarArtistaDTO.java`, `CriarMusicaDTO.java`, `AtualizarMusicaDTO.java` — DTOs sem validação; só o login usa `@Valid`, e sem constraints no DTO ele não valida nada. Testado: nome vazio, e-mail `naoehemail` e senha de 1 caractere retornam 201; música com ano `-5` retorna 201. **Correção:** adicionar `@NotBlank`, `@Email`, `@Size` e `@Min` nos DTOs e `@Valid` nos controllers.
- [x] **Alta** ★ · `backend/src/main/resources/application.properties:17,20-23` — Segredo do JWT e senhas dos admins (`123456`) estão versionados e, portanto, no histórico do git. **Correção:** ler de variáveis de ambiente, sem valor padrão em produção, e trocar o segredo e as senhas já expostos.
- [x] **Alta** · `application.properties:4,8-9` e `security/SecurityConfig.java:43` — O console H2 está habilitado e público, com `sa`/`sa`, sem perfil separado para produção (`GET /h2-console/` sem token retorna 200 localmente). Se o Render usa essa configuração, qualquer pessoa pode acessar o banco. **Correção:** criar perfis `dev` e `prod`, habilitar o console só em `dev` e remover o `permitAll` fora dele.
- [x] **Alta** · `controller/UsuarioController.java:30-52` — Qualquer conta lista nome e e-mail de todos os usuários, e o cadastro é público, então qualquer pessoa consegue essa lista. Testado com um USER recém-criado. **Correção:** restringir `GET /usuarios`, `/usuarios/buscar` e `/usuarios/{id}` a ADMIN depois de migrar o frontend para `GET /meu-perfil`.
- [x] **Alta** · `security/SecurityConfig.java:32` — Sem `authenticationEntryPoint`, a falta de autenticação retorna 403 em vez de 401, e o mesmo vale para senha errada em `POST /login`. O cliente não distingue "não logado" de "sem permissão". **Correção:** configurar `exceptionHandling` com entry point 401 e tratar `BadCredentialsException` como 401.
- [x] **Média** · `backend/Dockerfile:13-21` e `application.properties:6` — O banco H2 em arquivo fica no sistema de arquivos do contêiner e não há volume configurado. Se o Render não montar um disco, contas e dados se perdem a cada deploy. **Correção:** usar o PostgreSQL já presente no `pom.xml` no perfil `prod`, com URL vinda de variável de ambiente.
- [ ] **Média** · `security/DataInitializerConfig.java:35` — Os admins e dados de exemplo são criados em qualquer ambiente. **Correção:** anotar com `@Profile("dev")` e criar o admin de produção por um processo separado.
- [ ] **Média** · `dto/DadosAutenticacao.java` — Os exemplos do Swagger, que é público, mostram `admin@wave.com` e `123456`, credenciais reais do seed. **Correção:** usar valores fictícios nos `@Schema(example = ...)`.

- [ ] **Média** · `security/TokenService.java:48` — O cálculo da expiração fixa o fuso `-03:00` sobre um `LocalDateTime` local. Com o servidor em UTC, o token duraria 5h em vez de 2h. **Correção:** usar `Instant.now().plus(2, ChronoUnit.HOURS)`.
- [x] **Média** · `controller/ArtistaController.java:51` e `controller/MusicaController.java:51` — O `POST` devolve `Location: /{id}`, mas não existe `GET /artistas/{id}` nem `GET /musicas/{id}`, embora o service já tenha `getArtistaById` e `getMusicaById`. **Correção:** expor os dois endpoints com `@Operation`.

- [ ] **Média** · `backend/src/test/java/br/com/fatec/wave/WaveApplicationTests.java` — Só há smoke test, e ele usa a mesma URL do banco local (`./wavedb`), já que não há configuração de teste. **Correção:** criar perfil `test` com H2 em memória e testes de autenticação, autorização e validação com MockMvc.
- [ ] **Baixa** · `dto/CriarUsuarioDTO.java` e `dto/AtualizarUsuarioDTO.java` — `@Size(max = 72)` conta caracteres, mas o limite do BCrypt é de 72 bytes.
